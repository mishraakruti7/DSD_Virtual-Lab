TASK 28 — ACCESSIBILITY (target WCAG 2.2 AA)
===============================================================================
Known gaps found in the audit (fix all, then verify with tools):
 - 202 <button> elements and none has aria-label; many are icon-only.
 - 23 uses of `outline-none` remove the focus indicator.
 - Navbar dropdowns open on mouse hover only.
 - Inputs without associated labels in several places.
28a. STRUCTURE: <html lang="en">, a visible "Skip to main content" link,
   landmarks (header, nav, main, footer), one h1 per page with a logical
   heading order, descriptive page titles, focus moved to the page heading
   on route change, visible breadcrumbs where pages are nested.
28b. KEYBOARD: everything usable without a mouse. Replace every
   `outline-none` with a visible :focus-visible ring (≥3:1 contrast, 2px).
   Dropdown menus open on click, Enter/Space and arrow keys, close on Escape,
   expose aria-expanded/aria-haspopup, and never rely on hover. Modals, the
   tutor panel and the quick-search palette trap focus, close on Escape and
   return focus to the opener; use correct roles (dialog, combobox/listbox).
28c. FORMS: every input has a visible <label> (not placeholder-only), correct
   type and autocomplete values (email, current-password, new-password,
   name), required fields marked in text and aria-required, errors shown in
   text next to the field, linked with aria-describedby, announced via
   aria-live, and the first error receives focus on submit. Password
   show/hide button has an accessible name and state. Never auto-submit or
   time out forms without warning.
28d. BUTTON AND LINK LABELS: clear, specific verbs. Icon-only buttons get
   aria-label (e.g. "Open AI tutor", "Zoom in", "Undo last wire", "Close
   panel"). Replace vague labels: "Place" → "Place resistor on breadboard";
   "Verify" → "Verify circuit"; "Reset" → "Reset zoom" or "Reset circuit"
   as appropriate; "Submit" → "Send feedback"; "More" → "More pages". No
   "click here". Links that open a new tab say so.
28e. IMAGES AND GRAPHICS: meaningful images get specific alt text; purely
   decorative images and icons get alt="" / aria-hidden. Each circuit
   diagram or SVG gets a title/aria-label and a short text description of
   what it shows (and a data table or text equivalent for charts and truth
   tables; use <th scope> on tables). Gallery images each need unique alt
   text. Provide a text summary of any breadboard preset.
28f. COLOUR AND CONTRAST: audit every text/background pair in light AND dark
   mode — normal text ≥4.5:1, large text and UI components/focus rings/
   icons ≥3:1. Fix by adjusting existing design tokens (not by adding random
   colours). Check specifically: gradient headings (bg-clip-text), cream/
   amber warning cards, status badges (HIGH/LOW, Warning), disabled states,
   placeholder text, module accent colours. Do not use colour alone to carry
   meaning (wire colours, LED on/off, HIGH/LOW, pass/fail) — add text,
   icons or patterns.
28g. MOTION AND SENSORY: honour prefers-reduced-motion (disable parallax,
   pulsing, auto-advancing "Did you know" carousels or give pause controls);
   sound effects default OFF or clearly toggleable (keep the existing
   toggle); text can scale to 200% without breaking layout; touch targets
   at least 24x24px (44px preferred).
28h. DYNAMIC CONTENT: Circuit Health issues, toasts, quiz feedback and tutor
   replies are announced through polite aria-live regions.
28i. THE BREADBOARD CANVAS (hardest part — be honest about it): drag-and-drop
   alone is not enough (WCAG 2.2 requires a non-dragging alternative). Add:
   (1) click-to-place from the palette with a "Place at selected hole"
   action; (2) a "Parts and connections" panel listing placed parts and
   wires as real focusable list items with Move/Rotate/Delete buttons;
   (3) a keyboard "Add wire" dialog where the user picks From-pin and To-pin
   from labelled dropdowns; (4) arrow-key navigation across holes with the
   focused hole announced ("row 12, column c"). Document anything still not
   keyboard-operable in the Accessibility Statement.
28j. VERIFY: add eslint-plugin-jsx-a11y, run axe-core (via Playwright or
   Vitest) on every route in light/dark, run Lighthouse accessibility, and
   do a manual keyboard-only pass plus a screen-reader pass (NVDA/VoiceOver).
   Fix all critical/serious findings; list the rest in docs/A11Y_REPORT.md.
